# 提示词：对外交付版详细设计

> 用途：生成给甲方评审 / 验收用的项目级详细设计文档。
> 与技能的关系：保留 code-to-doc-generator 的 FACT/INFER 标注、保存路径与同步检查，仅覆盖其 LLD 默认章节模板与默认受众。

---

```text
请用 code-to-doc-generator 技能，为 <项目路径> 生成一份【对外交付版】项目级详细设计文档。

【文档类型】LLD 详细设计。类型已明确，直接开始，不要再追问文档类型。

【目标读者】甲方业务负责人、评审专家、验收人员，以及客户方的技术对接人。
假定读者了解业务但未必了解本项目代码。

【核心用途】用于方案评审、合同交付、验收确认和后续运维交接。
读者读完应当能回答五个问题：
1. 这个系统解决什么业务问题、覆盖哪些场景；
2. 系统由哪些部分组成、如何协同、部署在哪里；
3. 每个功能的输入、处理、输出和业务规则是什么；
4. 性能、安全、可用性达到什么水平，依据是什么；
5. 哪些能力本版本不做、有哪些已知风险、如何应对与验收。

【章节结构】以下目录为准，覆盖技能中 LLD 默认的 7 章模板：

1. 引言（编写目的、设计范围、术语表、参考文档、版本记录）
2. 项目概述（业务背景与痛点、建设目标与成功标准、角色与典型场景、端到端业务流程、技术选型说明）
3. 总体设计（逻辑架构、模块划分与职责、部署拓扑、技术栈清单、关键设计决策与取舍）
4. 功能详细设计（逐功能：业务入口、处理流程、业务规则、输出物、状态变化、异常与提示）
5. 核心组件详细设计（组件职责、能力清单、协作时序、提示词/规则设计要点）
6. 关键机制详细设计（状态流转、并发与顺序、重试与超时、降级与兜底、幂等与去重）
7. 数据设计（数据实体、字段说明、索引与约束、实体关系图、数据生命周期与保留策略）
8. 接口设计（每个接口：用途、请求参数表、返回结构、错误码表、调用示例、调用方注意事项）
9. 非功能设计（性能指标与容量假设、可用性、安全与权限、可观测性、扩展性，每项给目标值与依据）
10. 异常与边界设计（异常分类、用户可见提示、恢复方式、已知边界）
11. 测试与验收设计（测试分层、关键验收场景、验收标准 AC-01 起编号、每条可判定）
12. 风险与应对（对外可见风险、影响范围、应对措施、责任方与计划）
13. 部署与运维（环境要求、部署步骤、配置项说明、健康检查、常见问题处理）
14. 附录（错误码总表、配置项总表、术语索引、证据索引）

【刚性要求】
- 开头加一张「LLD 模板章节映射」表，逐条说明上述章节如何覆盖 LLD 的
  模块概述 / 接口 / 数据结构 / 流程 / 状态机 / 异常 / 性能七要素。
- 第三轮分析不能只提炼接口签名，必须补齐：业务背景与目标、角色与用例、
  端到端业务流程、非功能指标、验收标准。这些是文档主体，接口只占其中一章。
- 正文使用"业务语言 + 模块语言"，不出现 Java 类名、方法名、包路径、代码行号；
  这些只允许出现在附录「证据索引」，且以"模块 → 源文件"的粒度呈现。
- 每个功能章节末尾给一张业务规则表（规则编号 | 触发条件 | 结果 | 异常处理）。
- 第 11 章验收标准必须可判定（给定/当/则，或明确阈值），不少于 10 条。

【证据与标注】
- 保留 〔FACT｜文件:行号〕 与 〔INFER〕，但正文只标注"关键结论级"事实，
  行号统一收进附录；正文 FACT 标注数量控制在 30 处以内。
- 凡"当前版本未实现/待完善"的内容，一律改写为"本版本范围之外"或"后续演进项"，
  并说明对客户的影响与替代方案。

【脱敏红线（必须遵守）】
- 不得出现任何真实密钥、Token、数据库口令、内网 IP、真实域名、个人手机号。
- 配置示例一律用 <占位符> 表示。
- 不得出现内部缺陷编号、内部工单号、内部人员姓名。

【体量基线】
- 不少于 1500 行；Mermaid 图不少于 8 张（端到端业务流程、逻辑架构、部署拓扑、
  核心时序、状态机、ER 图、验收流程、运维流程）；表格不少于 55 个。
- 语气克制、结论明确，不使用"可能""大概""暂时"等模糊表述；
  不确定处标 〔INFER〕 并写推断依据。

【禁止项】
- 不要只写 happy path，异常与边界必须成节。
- 不出现"TODO""FIXME""已知 bug""未测试"等内部措辞。
- 不因为技能默认 7 章模板就压缩章节。
- 不输出"待后续补充"。

【输出】
保存到 docs/<项目名>/详细设计-<系统名>-客户版.md；
同步更新 docs/knowledge-base.md 的文档导航。
生成后自检：脱敏红线、验收标准可判定性、FACT 数量、章节完整性，四项逐条汇报。
```
