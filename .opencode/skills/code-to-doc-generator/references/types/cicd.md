# 类型：CI/CD 流水线文档（`cicd`）

## 解决什么问题

回答"代码怎么从提交走到上线、每步做了什么、失败怎么回滚"。

## 默认参数

| scope 默认 | 受众默认 | 落点后缀 |
|---|---|---|
| `project` | `operator` | 无 |

## base 章节

1. 流水线总览（流程图 + 环境表）
2. CI 阶段（逐 Job）
3. CD 阶段（策略、提升规则、自动回滚）
4. 配置与密钥管理
5. 回滚手册
6. 常见故障排查

`subsystem` 追加：环境矩阵。
`project` 追加：制品与版本策略、安全与合规检查。

## 各章要点

**总览**：从 `git push` 到生产，标出人工卡点与自动门禁。环境表：环境 | 用途 | 触发条件 | 访问限制。

**CI**：触发条件、步骤、通过条件、产出物。明确"什么情况阻塞合并"。

**CD**：蓝绿 / 滚动 / 金丝雀；进入下一环境的条件；健康检查与自动回滚条件。

**配置与密钥**：只写来源（配置中心 / 环境变量 / Vault），不写值。密钥轮换流程单独一节。

**回滚**：触发条件 → 命令级步骤 → 数据库迁移的回滚注意事项。必须能在压力下直接执行。

## 现状与建议分离

项目没有流水线时：

```markdown
## 现状
当前无 CI 配置，构建与测试均手工执行。

## 建议方案
（以下尚未落地）
```

禁止把建议写成现状。

## 写作规范

- 步骤到命令级，不写"部署到服务器"
- 不复制密钥值
- 回滚步骤必须可执行，不能"联系运维处理"

## 常见失败

| 失败 | 纠正 |
|---|---|
| 把建议当现状 | 分节标注 |
| 回滚含糊 | 补命令与判断条件 |
| 漏掉跳过检查 | 记录 `skipTests`、`-Dskip` 等现实 |
| 密钥写进文档 | 改为来源说明 |

## 边界

- 镜像内容与运行参数 → `lld` 部署节
- 监控告警 → `slo`
- 编码约定 → `coding-guide`
