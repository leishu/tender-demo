# 类型：LLD 详细设计（`lld`）

## 解决什么问题

让一个有经验的开发者在不问人的情况下接手实现、联调或排障。回答"具体怎么做、边界在哪、失败会怎样"。

## 默认参数

| scope 默认 | 受众默认 | 叙事默认 | 落点后缀 |
|---|---|---|---|
| `module` | `dev` | `engineering` | 无 |

## base 章节（`module`）

1. 模块概述（系统位置、职责边界、上下游）
2. 接口设计（逐接口）
3. 数据结构（实体、字段约束、枚举、索引）
4. 核心流程（含异常路径、事务、并发）
5. 状态机（如有）
6. 异常处理策略（分类、错误码、恢复）
7. 性能与限制（容量假设、瓶颈、失效边界）

`subsystem` 追加：部署与运维、测试要点。
`project` 追加：业务背景与目标、非功能指标、验收标准、风险与应对、附录。

## 各章要点

**接口设计**：用途一句；参数表（名称 | 类型 | 必填 | 说明 | 约束）；返回结构；错误码表；幂等性；超时；调用示例。
项目未定义统一错误码时，降级为「HTTP 状态码 + 业务消息 + 异常类型」，并注明"项目未定义统一错误码"，不得自造。

**数据结构**：字段名、类型、可空、默认值、约束、索引；枚举列出全部取值与语义；`project` 范围给 DDL 与 ER 图。

**核心流程**：Mermaid 图必须包含失败分支；写清事务边界、幂等键、重试策略、并发控制。

**状态机**：`stateDiagram-v2`；状态语义、触发条件、非法转换的处理。

**异常处理**：可恢复 / 不可恢复；吞异常点；日志级别；用户可见提示。

**性能与限制**：给出数字或"未测量"，写清测量方式；列出失效边界（数据量、并发、超时）。

## 写作规范

- 每个接口必须能对照代码找到实现
- 流程图不止 happy path
- 并发场景明确是否需要锁或事务
- 关键结论附 `〔FACT〕`；未验证的性能数字标 `〔INFER〕`

## 常见失败

| 失败 | 后果 | 纠正 |
|---|---|---|
| 只写接口签名 | 变成 API 清单 | 补业务规则、异常、并发 |
| 照抄类结构 | 读者仍需读代码 | 按调用链组织，不按包结构 |
| 错误码凭空发明 | 联调对不上 | 降级为实际异常类型 |
| 性能数字无来源 | 不可信 | 标测量方式或 `〔INFER〕` |

## 边界

- 不做模块划分与选型论证 → 那是 `hld`
- 不做验收标准 → `project` 范围的验收节只写"如何验证本模块"，完整验收在 `test-doc`
- 不做需求描述 → `prd`

## 内部评审版附加规则

适用于 `audience=dev` 且用于**内部评审、发布准入判断**的 LLD。客户版用 `narrative=review`，不适用本节。

### 1. 待裁决项单列

`P0` 主表只放**已确认**的问题。状态为 `待裁决` 的项进入独立小节「待裁决清单」，不得与已确认 P0 混排。

| 要求 | 写法 |
|---|---|
| 位置 | 问题清单之后、发布准入结论之前，作为独立 H3 |
| 每条必含 | 待裁决问题（一句话，可回答是/否）、裁决人、裁决前默认处置、影响 |
| 默认处置 | 必须写明"裁决前按阻断处理"，不得写成"视情况而定" |
| 发布准入结论 | 必须说明"P0 已确认 N 项 + 待裁决 M 项，按阻断计共 N+M 项" |

理由：待裁决项留在 P0 主表里，会把"不可发布"变成可谈判的结论；单列后，结论仍可执行，裁决结果只改变清单归属，不改变当前判定。

### 2. 正文 `OBSERVE` 必须回指问题编号

正文（第 4、6、10 章等）出现的每个 `〔OBSERVE｜…〕`，紧邻位置必须写 `见 P0-xx` / `见 P1-xx` / `见 P2-xx`。

| 写法 | 判定 |
|---|---|
| `〔OBSERVE｜缺陷｜高｜已确认〕…（见 P0-06）` | 合格 |
| `〔OBSERVE｜缺陷｜高｜已确认〕…` | 不合格：无法确认是否被问题清单收录 |

第 11 章每项问题必须能反查到正文出现位置；只在第 11 章出现、正文无对应叙述的问题，应在第 11 章注明"仅清单项，无独立正文段落"。

### 3. 重复表只定义一次

同一张表（错误码总表、配置项总表、字段清单）在正文与附录中只保留**一处完整定义**。

| 情况 | 处理 |
|---|---|
| 两表内容完全相同 | 删除附录版，正文表后加一行"附录不再重复" |
| 两表列不同但场景重叠 | 合并为一张宽表，放在信息更全的一侧，另一侧改为一行引用 |
| 两表口径不同（如统计对象不同） | 不得并列展示；分别标注统计对象，或合并后增加"口径"列 |

错误码、配置项一律以**一处定义 + 他处引用**为准；引用处只写"见 X.Y"，不重复列值。

### 4. 统计口径必须自证

凡出现"N 个用例""N 个文件""N 项问题"这类计数，同一节内必须写清统计对象。

- 源码类数量 ≠ 残留报告数量，不得并列在同一列；
- 问题数按 `P0 + P1 + P2` 与"正文 OBSERVE 去重后数量"分别给，差异要解释；
- AC 表中不得混入"已知边界确认项"，后者单列一节。
