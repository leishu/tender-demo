# 类型：编码指南（`coding-guide`）

## 解决什么问题

让新贡献者写出与现有代码一致的实现，少踩已经踩过的坑。

## 默认参数

| scope 默认 | 受众默认 | 落点后缀 |
|---|---|---|
| `project` | `dev` | 无 |

## base 章节

1. 开发环境（版本、依赖、初始化、常用命令）
2. 项目结构（2–3 层目录树 + 放置规则）
3. 代码规范（命名、文件组织、注释）
4. 模块实现规范（每模块：正例、反例、原因、陷阱）
5. 关键依赖使用规范
6. 测试规范
7. 提交与 CR 规范

`project` 追加：分支与发布策略、脚手架与模板。

## 各章要点

**实现规范**：必须给代码片段。反例要写"为什么错"，不能只写"不要这样"。

**关键依赖**：项目特有的约定，例如"统一用 X 而非 Y"、"必须手动关闭 Z"。只写代码里真实存在的约定，不发明。

**测试规范**：文件位置与命名、必须覆盖的类型、Mock 边界、如何本地运行。

## 写作规范

- 从现有代码归纳，不写理想规范
- 每条规则给出处（哪个模块这样写），便于追溯
- 正例与反例成对出现

## 常见失败

| 失败 | 纠正 |
|---|---|
| 抄通用规范（阿里/Google） | 只留项目实际执行的 |
| 只有规则没有示例 | 补正反例 |
| 规范与代码不一致 | 以代码为准，或标为"待统一" |
| 遗漏构建陷阱 | 补构建、跳过检查等现状 |

## 边界

- 模块设计与接口 → `lld`
- 流水线配置 → `cicd`
- 架构约束 → `hld`
