# 类型：测试文档（`test-doc`）

## 解决什么问题

回答"要测什么、边界在哪、怎么判定通过、现在测到什么程度"。

## 默认参数

| scope 默认 | 受众默认 | 落点后缀 |
|---|---|---|
| `module` | `dev` | 无 |

## 变体

生成时确认变体，未指定则按通用测试文档。

| 变体 | 侧重 | 主要章节 |
|---|---|---|
| `bdd` | 行为描述 | 场景用 Given / When / Then |
| `sit` | 模块间集成 | 集成点、超时与降级、事务边界 |
| `e2e` | 完整旅程 | 起点状态 → 操作序列 → 终点状态 → 断言 |
| `uat` | 业务验收 | 业务语言、业务价值、验收标准映射 |

变体不改变 base 结构，只改变用例写法与重点章节的展开。

## base 章节

1. 测试范围（包含 / 不包含 / 环境要求）
2. 测试策略与环境（分层、数据准备、入口命令）
3. 功能用例（逐模块）
4. 边界与异常用例
5. 集成测试点
6. 回归清单
7. 已知问题与测试局限

`subsystem` 追加：环境与数据准备、自动化入口。
`project` 追加：验收标准映射、测试数据与账号管理、CI 门禁。

## 各章要点

**用例表**：用例 ID | 场景 | 前置条件 | 步骤 | 预期结果 | 优先级。

预期结果必须可观察。禁止"正常运行""无异常"。

**边界**：最小值、最大值、空值、越界、并发、权限越权、状态非法。边界值必须来自代码中的实际校验，不能凭经验编。

**现有覆盖**：区分三种状态：

| 状态 | 判定 |
|---|---|
| 有测试且有效 | 能独立运行、断言明确 |
| 有测试但无效 | 未加载容器、硬编码地址、只断言不失败 |
| 无测试 | 完全没有 |

三者分开写，不能统一写成"覆盖不足"。

## 写作规范

- 优先级：P0 核心流程不可用；P1 主要功能异常；P2 边缘
- 无法自动化的场景单列，说明原因与人工步骤
- 测试数据用占位符，不写真实账号

## 常见失败

| 失败 | 纠正 |
|---|---|
| 用例只有 happy path | 每功能补异常与边界 |
| 预期结果模糊 | 改为可观察断言 |
| 把无效测试算作覆盖 | 按三态拆分 |
| 用例与代码校验不一致 | 回到代码确认边界值 |

## 边界

- 验收标准定义 → `prd`
- 实现细节 → `lld`
- 流水线执行 → `cicd`
