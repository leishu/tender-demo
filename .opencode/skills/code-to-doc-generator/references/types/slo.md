# 类型：SLI / SLO 监控文档（`slo`）

## 解决什么问题

回答"可靠性目标是什么、用什么指标度量、什么时候告警、出事怎么办"。

## 默认参数

| scope 默认 | 受众默认 | 落点后缀 |
|---|---|---|
| `subsystem` | `operator` | 无 |

## base 章节

1. 服务依赖拓扑（图 + 关键路径标注）
2. SLI 指标定义
3. SLO 目标
4. 告警规则
5. 关键大盘
6. 事故响应指南

`subsystem` 追加：容量与依赖假设。
`project` 追加：错误预算政策、容量规划、成本。

## 各章要点

**SLI**：指标名 | 计算方式 | 数据来源（日志/指标/Trace）| 采集频率。

**SLO**：服务 | SLI | 目标值 | 错误预算 | 责任方。目标必须是百分比或具体数值。

**来源标注**：每个数值必须标注来源之一：

| 来源 | 含义 |
|---|---|
| 已有配置 | 代码或配置中真实存在 |
| 行业基线 | 通用经验值，需注明依据 |
| 建议值 | 本文建议，尚未落地 |

没有来源的数值不得写入。

**告警**：告警名 | 触发条件 | 严重度 | 通知渠道 | 响应时限 | 处理步骤链接。

**事故响应**：常见故障模式 + 排查流程图 + 降级与回滚步骤。

## 写作规范

- 阈值从代码提取：超时配置、重试次数、连接池大小
- 告警必须附处置步骤，不能只报警
- 项目无监控时，明确写"当前无监控，以下为建议方案"，不得伪装成现状

## 常见失败

| 失败 | 纠正 |
|---|---|
| 编造 SLO 数值 | 标来源，或写"建议值" |
| 告警阈值无依据 | 从超时/容量配置推导 |
| 只写指标不写处置 | 每条告警配步骤 |
| 把建议当现状 | 分节标注 |

## 边界

- 部署步骤 → `cicd`
- 功能行为 → `lld`
- 运营操作 → `operations-manual`
