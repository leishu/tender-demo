# 类型：DDD 领域设计（`ddd`）

## 解决什么问题

让架构师与领域专家就"边界怎么划、聚合是什么、不变量在哪"达成一致。

## 默认参数

| scope 默认 | 受众默认 | 落点后缀 |
|---|---|---|
| `subsystem` | `architect` | 无 |

`module` 不适用，最低 `subsystem`。

## base 章节

1. 战略设计（核心域 / 支撑域 / 通用域）
2. 限界上下文（每个上下文一节）
3. 战术设计（聚合根、实体、值对象、领域事件、领域服务、仓储契约）
4. 通用语言词汇表
5. 待裁决问题

`subsystem` 追加：上下文映射全景。
`project` 追加：领域事件流、模型演进与迁移。

## 各章要点

**上下文划分**：说明划分依据（一致性边界 / 团队边界 / 业务能力），不能只画图。

**聚合**：列出聚合根、内部实体、不变量、事务边界。聚合之间只通过 ID 引用。

**领域事件**：事件名 | 触发条件 | 携带数据 | 消费方 | 是否幂等。

**通用语言**：项目术语 → 业务定义 → 代码中对应符号；一词多义必须拆开。

## 写作规范

- 从代码推断的模型大量使用 `〔INFER〕`，需领域专家校准
- **禁止**仅凭包名或目录名断定限界上下文；必须有业务规则或事务边界佐证，否则列为待裁决
- 聚合边界必须说明"为什么在这里切"

## 常见失败

| 失败 | 纠正 |
|---|---|
| 按包结构画上下文 | 改为按业务能力，标注依据 |
| 聚合过大或过小 | 用事务边界与不变量校验 |
| 事件没有消费方 | 补消费方或标记为"仅记录" |
| 术语表只有名词 | 补定义与代码映射 |

## 边界

- 部署与选型 → `hld`
- 表结构与索引 → `lld`
- 业务流程 → `prd`
