# 受众渲染档位

**唯一渲染依据。** 受众不改变章节集合（那由 `composition-matrix.md` 决定），也不决定章节顺序（那由 `narrative` 决定），只改变同样几章**怎么写**。

---

## 一、四档配置

| 开关 | `dev` 开发 | `architect` 架构 | `business` 业务/验收 | `operator` 运维/运营 |
|---|---|---|---|---|
| 术语层 | 类名、包名、方法名直接用 | 模块名 + 关键组件名，类名按需 | 业务语言，技术词首次出现给解释 | 对象名 + 操作名，不出现代码结构 |
| 证据密度 | 行级 `FACT` 不设上限 | 关键结论 + 架构决策处标注 | 结论级，正文 0 处锚点，全量进附录 | 命令级 + 配置项级 |
| 问题口径 | 缺陷清单 + 发布准入结论 | 设计债 + trade-off + 演进建议 | 风险与应对 + 影响 + 计划 | 故障模式 + 处置步骤 |
| 展开深度 | 方法级：分支、异常、并发 | 组件级：职责、交互、边界 | 场景级：输入、结果、规则 | 操作级：步骤、判据、回滚 |
| 脱敏 | 不复制密钥值，可指出现象 | 同 `dev` | 全脱敏：无密钥、内网、人名、工单号 | 可含内网网段，不含凭据 |

## 三、各开关的具体做法

### 术语层

- `dev`：`TenderController#parse` 直接出现
- `architect`：`解析入口（TenderController）`
- `business`：`解析入口`；附录给"业务名 → 模块 → 源文件"映射
- `operator`：`解析任务`；不出现 HTTP、SSE 等协议名

### 证据密度

- `dev`：每个关键结论附 `〔FACT｜文件#符号:行号｜基线〕`
- `architect`：ADR、跨模块约束、性能数字必须附证据；实现细节可省略
- `business`：只对"影响承诺"的事实标注；全量锚点收进附录「证据索引」；**正文不出现证据编号**
- `operator`：配置项、超时值、阈值必须附证据

### 问题口径

同一批问题，四种写法：

| 受众 | 写法 |
|---|---|
| `dev` | `P0：构建跳过测试（pom.xml:12），阻断发布` |
| `architect` | `测试门禁缺失，建议在 CI 增加 verify 阶段` |
| `business` | `当前版本以手工验证为主，自动化回归将在下一阶段补齐` |
| `operator` | `发布前需人工执行冒烟清单，见附录 B` |

**不得改变事实，只改变呈现。** 把 P0 写成"下一阶段优化"属于失真，必须同时给出影响与时间点。

### 展开深度

- `dev`：写出 `switch` 分支、异常类型、事务边界
- `architect`：写组件契约与失败模式，不写具体分支
- `business`：写"输入什么、得到什么、什么情况下拿不到"
- `operator`：写"怎么判断、怎么处理、怎么回滚"

## 四、`business` 的两条硬规则

### 规则 1：正文不引用证据编号

证据索引是附录里的**技术复核附件**，不是正文的导航。业务读者不应为了看懂一句话去翻 E-01。

| 场景 | 错误写法 | 正确写法 |
|---|---|---|
| 正文引用证据 | "事件类型约定见 E-01、E-02" | "事件类型约定见 4.1" |
| 表格引用证据 | "写入路径见 E-09" | "写入路径见 4.5" |
| 风险引用证据 | "见 E-22" | "见 13.2" |

E 编号只允许出现在附录证据索引内部。生成后用校验脚本的 `evidence-ref-body` 检查。

### 规则 2：未测量指标必须给验收后果

业务版不承担"工程上未测量"的表述，承担的是"验收时怎么判"。

| 错误写法 | 正确写法 |
|---|---|
| 目标值 30 秒，当前未测量 | 目标值 30 秒（验收时实测；超过 30 秒按 AC-01 判定不通过） |
| 并发能力未验证 | 单实例 5 路（验收时压测；未达到按 AC-06 判定不通过） |
| 可用性 99% | 月度可用性 99%（以监控月报为准；低于 99% 触发服务抵扣条款） |

目标值本身没有代码依据时，标 `〔INFER〕` 并写推断依据；有依据时只写章节交叉引用，不写 E 编号。

> 配套要求：`business` 文档默认使用 `narrative=review`，风险章中责任方为甲方的条目必须汇总成"上线前甲方准备清单"。骨架见 `composition-matrix.md` 第六节。

## 五、约束

1. **受众不删章节。** 只能压缩表述；删章节需用户显式要求，并在参数卡标注。
2. **受众不降低事实强度。** 允许换词，不允许把缺陷说成特性。
3. **一文档一受众。** 需要两种读者时，生成两份，用 `package` 模式索引；不要写"本节供开发阅读"的混排文档。
