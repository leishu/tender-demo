# 证据体系

**唯一标注依据。** 所有文档中的事实、推断、问题都使用本文件的语法；其他文件只引用，不重复定义。

---

## 一、三级标注

| 标记 | 含义 | 使用条件 |
|---|---|---|
| `〔FACT｜锚点〕` | 从代码、配置、运行结果直接验证的事实 | 能在当前代码树中定位 |
| `〔INFER〕` | 合理推断，未经人确认 | 附推断依据与验证方式 |
| `〔OBSERVE｜类型｜严重度｜状态〕` | 发现的问题、缺口、风险 | 需要人裁决或跟踪 |

### 锚点语法

```
〔FACT｜<路径>#<符号>:<起>[-<止>]｜<基线>〕
```

- `路径`：相对项目根，正斜杠
- `符号`：类名 / 方法名 / 配置键，可省略
- `起`-`止`：1 起始行号；单行可省略 `止`
- `基线`：`git:<短哈希>` / `sha256:<前8位>` / `snapshot:<YYYY-MM-DD>`

推荐写法：

```
〔FACT｜src/main/java/org/example/controller/TenderController.java#parse:76-89｜git:a1b2c3d〕
〔FACT｜pom.xml#maven.compiler.release:21｜git:a1b2c3d〕
```

向后兼容（旧文档无需改写）：

```
〔FACT｜src/main/java/org/example/controller/TenderController.java:76-89〕
〔FACT｜pom.xml:12〕
```

### 问题标注

```
〔OBSERVE｜<类型>｜<严重度>｜<状态>〕
```

| 字段 | 闭合枚举 |
|---|---|
| 类型 | `缺陷` `债务` `缺口` `异味` `风险` `性能` |
| 严重度 | `高` `中` `低` |
| 状态 | `待裁决` `已确认` `已修复` `已忽略` |

与优先级换算：`高 → P0`，`中 → P1`，`低 → P2`。

类型定义：

- `缺陷`：逻辑错误、自相矛盾、违反自身约束
- `债务`：TODO/FIXME、临时方案、过时引用
- `缺口`：声明了未落实，或只做了一半
- `异味`：结构或命名值得改进，不阻塞
- `风险`：安全、合规、运维、可持续性隐患
- `性能`：效率可疑点

## 二、密度规则

| 受众 | 规则 |
|---|---|
| `dev` | 关键结论必标；实现细节选标；同一事实只标一次 |
| `architect` | 决策、约束、性能数字必标 |
| `business` | 只标影响承诺的事实；**正文 0 处锚点**，全量进附录证据索引 |
| `operator` | 配置项、阈值、超时必标 |

判定"关键结论"的三条标准，命中任一即标：

1. 读者会据此做决定（选型、验收、排期）
2. 数字或阈值（超时、并发、容量、限额）
3. 与直觉相反的行为（默认值、降级、静默失败）

**不标**：显而易见的 CRUD、纯展示代码、框架样板。

## 三、行号失效与基线

行号会随代码漂移。三条规则：

1. 锚点必须带基线；无基线时，行号视为"生成时快照"，不得作为长期引用。
2. 优先写符号名：符号可重新定位，行号不能。
3. 校验脚本按三态处理：

| 状态 | 条件 | 处理 |
|---|---|---|
| `ok` | 文件存在，行号在范围内，符号可检索 | 通过 |
| `unverifiable` | 非 Git / 生成代码 / 动态语言定位不到 | 警告，记录 |
| `missing` | 文件不存在、行号越界、符号找不到 | 错误，必须修复 |

## 四、证据索引与正文引用

`project` 范围的文档必须在附录提供证据索引，正文只保留结论：

```markdown
## 附录 C 证据索引

| 编号 | 结论 | 锚点 | 章节 |
|---|---|---|---|
| E-01 | 解析入口为 SSE 流式返回 | `〔FACT｜...TenderController.java#parse:76-89〕` | 4.2 |
| E-02 | 构建阶段跳过测试 | `〔FACT｜pom.xml:12〕` | 11.1 |
```

编号 `E-xx` **只在附录定义一次**，其他章节不得重复定义。

### 正文引用规则（按受众分叉）

| 受众 | 正文能否出现 `见 E-01` | 替代写法 |
|---|---|---|
| `dev` | 可以 | `见 E-01` |
| `architect` | 可以 | `见 E-01` |
| `operator` | 可以 | `见 E-01`，或直接给配置键 |
| `business` | **不可以** | 只写章节交叉引用，如 `见 4.1` |

`business` 视角下，证据索引是**技术复核附件**，供技术评委与第三方复核，不是正文导航。业务读者不应为看懂一句话去翻附录。

> 校验：`business` 文档正文出现 `见 E-\d+` 时，`validate_doc.py` 报 `evidence-ref-body`（error）。附录证据索引表内的 `E-xx` 列不算正文引用。

## 六、禁止

1. 用 `〔FACT〕` 标注推测内容。
2. 同一事实在多个章节重复贴锚点（用章节交叉引用）。
3. 无基线的行号出现在"验收依据"类章节。
4. 把 `〔OBSERVE〕` 写成情绪化评价（"代码很烂"），只写现象、影响、建议。
