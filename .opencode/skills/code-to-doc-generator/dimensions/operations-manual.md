# 运营手册分析维度

仅用于 `operations-manual` 与 `admin-quick-reference`。其他类型使用 `references/types/` 中各自的维度。

对每个业务模块，按七个维度提取。

---

## 维度 1：操作基础

- 功能入口（菜单路径 / 按钮位置）
- 权限要求（哪类角色可操作）
- 操作步骤（有序）
- 表单字段（含义、必填、可选值）

## 维度 2：状态影响

- 操作后哪些数据或状态变化
- 生效时机：立即 / 下次请求 / 下次同步
- 是否可撤销，如何撤销
- 极端值（0 / 空 / 最大值）意味着什么

## 维度 3：危险等级

| 等级 | 标注 | 判定 |
|---|---|---|
| 🔴 危险 | `> ⚠️ **危险**：...` | 不可逆：删除、禁用、清空 |
| 🟡 注意 | `> 📌 **注意**：...` | 影响面广，需了解后果 |
| 🟢 安全 | 不标 | 可随时撤销 |

## 维度 4：设计背景

回答"为什么需要这个功能，没有会怎样"。

- 1–3 句，聚焦痛点
- 只从代码、注释、UI 能推断出明确痛点时写，否则省略
- 格式：`> 💡 **设计背景**：...`

## 维度 5：业务规则与算法

- 系统自动执行的逻辑：公式、条件、上下限
- 必须**命名**底层策略，不能只写"影响计费"
- 例：修改分组倍率 → 触发「计费结算策略」

## 维度 6：关联影响

表格：影响范围 | 具体变化。

## 维度 7：已知局限

- 当前版本做不到的事
- 临时绕过方案
- 什么场景下会失效

**有则写，无则省略；上限 5 条，不设下限。** 不允许为凑数编造。

---

## 章节结构要求

每章固定以两节开头：

### 🔗 前置依赖链路

```
[上游模块] ➔ [上游模块] ➔ **[当前]** ➔ [下游模块]
```

- 标注总深度 N
- 每个前置条件写"有 / 无"两种结果
- 重点揭示缺失时的意外副作用

### 📊 影响追踪矩阵

| 本模块配置项 | 影响的点 | 影响的功能 | 影响的算法/策略 |
|---|---|---|---|

第四列必须写策略名 + 机制，不能重复第三列。

## 术语

面向不懂技术的读者，替换规则只在本文件定义：

| 禁止 | 替换 |
|---|---|
| API / 接口 | 调用方式 / 接入方式 |
| Token | 令牌 / 凭证 |
| JSON | 配置内容 |
| HTTP / 请求 | 操作 / 访问 |
| 数据库 | 系统数据（必要时保留"数据库"） |
| 缓存 | 临时记录（必要时保留"缓存"） |
| 中间件 | 描述其效果，不提名称 |
| Webhook | 回调通知 |
| 正则 | 匹配规则 |
| 限流 | 请求频率上限 |

两者冲突时以本表为准；其他文件不得再定义第二份术语表。
